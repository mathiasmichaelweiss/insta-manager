Локальное приложение для работы со своим Instagram: список постов с метаданными,
комментарии, статистика поста и транскрипт видео через OpenAI. Всё, что
загружается и выгружается — в JSON.

## Что нужно от Instagram

Аккаунт должен быть **Professional (Business или Creator)**. Старый Instagram
Basic Display API отключён в декабре 2024 — ни комментариев, ни статистики он не
даёт.

Приложение работает с обеими действующими схемами Meta и определяет нужную по
самому маркеру доступа:

| Схема | Хост | Когда использовать |
| --- | --- | --- |
| **Instagram API with Instagram login** | `graph.instagram.com` | основной путь: маркер выдаётся прямо в дашборде |
| Instagram API with Facebook login | `graph.facebook.com` | если аккаунт связан с Facebook-страницей и вы работаете через Page token |

### Разрешения (Instagram login)

| Разрешение | Зачем |
| --- | --- |
| `instagram_business_basic` | список постов и метаданные |
| `instagram_business_manage_comments` | комментарии и ответы |
| `instagram_business_manage_insights` | **статистика поста** |

`instagram_business_manage_insights` — отдельное разрешение, и в стартовом наборе
дашборда его нет: там перечислены `basic`, `manage_comments` и
`manage_messages`. Добавьте его в «Разрешения и функции», иначе посты и
комментарии загрузятся, а статистика будет отдавать ошибку прав.
`instagram_business_manage_messages` этому приложению не нужен.

**После добавления разрешения маркер доступа нужно сгенерировать заново** —
выданный ранее не получит новых прав.

Для Facebook login набор другой: `instagram_basic`,
`instagram_manage_comments`, `instagram_manage_insights`, `pages_show_list`,
`pages_read_engagement`.

### Режим приложения: Development vs Live

**Для комментариев приложение должно быть в режиме Live.** Это самая частая
причина «пустых» комментариев.

В режиме Development API отдаёт только данные владельца приложения. Посты и
статистика — ваши собственные, поэтому они приходят нормально. А комментарии
написаны другими людьми: Instagram перебирает их в пагинации (курсоры и число
страниц совпадают с `comments_count`), но **вырезает содержимое и не возвращает
никакой ошибки**. Выглядит как «комментариев нет».

**Live не означает публикацию.** Приложение не появляется ни в каком каталоге,
App Review проходить не нужно. Кто может им пользоваться, определяет уровень
доступа: при Standard Access это только аккаунты с ролью в приложении, то есть
только вы. Приложение продолжает работать на `localhost`.

Как переключить: дашборд → «Настройки → Основное» → указать **URL политики
конфиденциальности** → переключатель вверху в режим Live.

Готовый текст политики лежит в [`docs/privacy-policy.md`](docs/privacy-policy.md).
Его достаточно опубликовать по любому https-адресу — например, создать
публичный [GitHub Gist](https://gist.github.com/) и указать ссылку на него.
Meta проверяет только то, что страница открывается.

Приложение распознаёт этот случай: если Instagram вернул 0 комментариев при
ненулевом `comments_count`, вместо пустого списка показывается предупреждение с
объяснением.

## Запуск

```bash
cp .env.example .env.local   # заполнить ключи
npm install
npm run dev                  # http://localhost:3000
```

Минимум для старта — `OPENAI_API_KEY` (для транскриптов) и маркер доступа.

**Основной способ — маркер из дашборда.** В приложении на developers.facebook.com:
*API setup with Instagram business login* → шаг 2 «Сгенерируйте маркеры доступа»
→ добавьте свой аккаунт (ему нужна роль тестировщика на вкладке «Роли») →
Generate token. Такой маркер **долгоживущий, 60 дней**. Вставьте его на
`/settings` или положите в `IG_ACCESS_TOKEN` в `.env.local`.

На `/settings` есть кнопка **«Продлить маркер на 60 дней»** — сбрасывает срок
жизни без повторной авторизации (работает, когда маркеру уже больше суток).

**Альтернатива — OAuth.** Задать `IG_APP_ID`/`IG_APP_SECRET` (или
`FB_APP_ID`/`FB_APP_SECRET`) и нажать «Войти» на `/settings`. Учтите: Instagram
требует **https** в Redirect URI, поэтому вход через Instagram на
`http://localhost` не работает — понадобится туннель вроде ngrok. Facebook login
на localhost работает.

Подключённый аккаунт сохраняется в `data/account.json`. Вся папка `data/` — в
`.gitignore`, потому что содержит маркер доступа.

## Страницы

**`/posts` — все посты.** Таблица с метаданными: превью, описание, тип
(Фото / Видео / Карусель + Reels / Stories), дата, лайки, комментарии и отметки о
том, что уже скачано на диск. Сортировка по любому столбцу, поиск по описанию и id.

- **Загрузить все комментарии** — проходит по всем постам, у которых
  `comments_count > 0`, и сохраняет комментарии каждого. Прогресс идёт живым
  NDJSON-потоком, ошибка на одном посте не останавливает остальные.
- **Выгрузить посты JSON** / **Выгрузить все комментарии JSON** — скачивание файлом.

**`/posts/[id]` — пост.** Превью (видео проигрывается), метаданные, описание и три
блока с кнопками:

- **Статистика** — охват, просмотры, лайки, сохранения, репосты, переходы в
  профиль и т.д. Набор метрик зависит от типа поста; те, что Instagram не отдал,
  показываются отдельным списком с причиной. Кнопка **Выгрузить статистику**.
- **Транскрипт видео** (только для VIDEO / Reels) — скачивает видео по `media_url`
  и отправляет в OpenAI. `whisper-1` возвращает таймкоды сегментов, их можно
  переключать. Кнопка **Выгрузить транскрипт**.
- **Комментарии** — с ответами, поиском по тексту и автору. Кнопка **Выгрузить
  комментарии**.

Плюс **Выгрузить всё JSON** — пост, статистика, комментарии и транскрипт одним файлом.

**`/topics` — темы комментариев.** Разбирает весь архив комментариев на
повторяющиеся темы через OpenAI и показывает их по убыванию размера: сколько
комментариев, сколько из них вопросов, под сколькими постами встречается, плюс
примеры. Перед запуском показывает стоимость. Каждая частая группа вопросов —
готовая тема для ролика.

**`/drafts` — черновики и бриф для ИИ-агента.** Загрузите видео, которого ещё нет
в Instagram, — приложение расшифрует речь. Сам файл не сохраняется, только
транскрипт.

На той же странице — **порядок работы с ИИ-агентом и четыре готовых промпта** под
копирование: оценить черновик перед публикацией, найти темы для новых роликов,
вывести правила из сработавших роликов, проверить тему на повтор. Промпты
написаны под структуру брифа и называют конкретные поля, чтобы агент опирался на
ваши цифры.

Кнопка **«Бриф для агента»** собирает один JSON со всем сразу: медианы аккаунта,
все посты с метриками (охват, досмотр, ER, сохранения и репосты на охват),
полные транскрипты и хуки, темы комментариев с числом вопросов — и транскрипт
черновика. Посты отсортированы по охвату, лучшие сверху. Это тот файл, который
отдаётся ИИ-агенту, чтобы он оценил новое видео на фоне того, что уже сработало.
Доступен и без черновика: `/api/export?kind=brief`.

**`/settings`** — подключение аккаунта и состояние окружения.

## Где лежат данные

```
data/
  account.json              токен и id аккаунта
  media.json                список всех постов
  comments/<mediaId>.json
  insights/<mediaId>.json
  transcripts/<mediaId>.json
```

Кнопки «Выгрузить» отдают ровно эти файлы (или их объединение) с
`Content-Disposition: attachment`.

## Транскрипция

Лимит OpenAI на аудиофайл — 25 МБ. Длинные Reels в него не влезают, поэтому если
видео больше, приложение вырезает аудиодорожку через `ffmpeg`
(`brew install ffmpeg`) и отправляет только её. Без ffmpeg такое видео вернёт
понятную ошибку вместо падения.

Модель меняется через `OPENAI_TRANSCRIBE_MODEL`. `whisper-1` — с таймкодами,
`gpt-4o-transcribe` — точнее, но только сплошным текстом.

## Заметки по API

- Версия API задаётся в `GRAPH_API_VERSION` (по умолчанию `v23.0`, работает на
  обоих хостах). Meta выводит версии из строя примерно через два года — если
  запросы начнут падать, поднимите номер.
- Набор полей и метрик меняется от версии к версии. Приложение это переживает:
  если API ругается на несуществующее поле, оно убирается из запроса и запрос
  повторяется; если пакет метрик отклонён целиком, каждая метрика запрашивается
  отдельно и в результат попадают все, что ответили. Отказы запоминаются на
  время работы процесса, чтобы массовая загрузка не переспрашивала одно и то же
  на каждом посте.
- Ошибка прав (код 10 или 200) распознаётся отдельно и возвращает 403 с
  подсказкой, какое разрешение добавить — вместо того чтобы выглядеть как сбой.
- Лимиты вызовов у Instagram небольшие. Массовая загрузка комментариев идёт
  последовательно; при упоре в лимит приложение сообщает об этом прямо
  (HTTP 429) вместо тихого обрыва.
- `media_url` — временные ссылки от CDN Meta. Перед транскрипцией пост всегда
  перечитывается из API, чтобы ссылка была свежей.
